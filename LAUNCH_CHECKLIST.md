# Launch checklist

Pre-submission gate for a Chrome Web Store release. Full deploy detail is in
`docs/DEPLOY.md`; listing copy is in `STORE_LISTING.md`.

## 1. Green build

- [ ] `npm run typecheck && npm test` (Tier 1) green.
- [ ] `cd service && pytest` green (if the service changed).
- [ ] `cd monitor && npm run monitor` is 4/4 green against live Google
      (or note any expected-skip), per `docs/TEST_PLAN.md`.

## 2. Manual release gate (MANDATORY — blocks packaging)

- [ ] Run the manual checklist in `docs/TEST_PLAN.md` against the **packed** zip
      loaded unpacked. In **each of Docs, Sheets, and Slides**: the Brand
      LABEL is visible above the row, swatch tooltips show the brand names, and
      a brand color actually applies. Options edit reflects on next picker
      open; popup toggle + feedback page work.
- [ ] `npm run package` enforces this (refuses without confirmation /
      `SMOKE_CHECKED=1`). Never confirm the prompt without actually having done
      the three-app check on the current tree.

## 3. Version + changelog

- [ ] `manifest.json` / `package.json` already carry the new version: it is
      bumped in the first commit after a release, not here (semver,
      default to a patch). Every CWS upload needs a higher version string; burned
      numbers can't be reused.
- [ ] `CHANGELOG.md` has a `[<version>] — Unreleased` section and, for a
      user-visible change, `RELEASE_NOTES.md` has a `<version>` entry.
      `scripts/release.sh <version>` dates both headings at the cut.

## 4. Assets + listing

- [x] Icons final: the palette-stripe mark generated by `npm run icons` was
      promoted to the shipping icon (decision 2026-08-09, bd
      workspace-custom-palette-ejv) — it matches the runtime toolbar repaint.
      Regenerate only if `config/palette.default.json`'s leading colors change.
- [ ] Screenshots ready (Brand row open in a Sheet, options page).
- [ ] `STORE_LISTING.md` copy current; permission justifications + the
      "config is data, not code" review note ready to paste.

## 5. Package

- [ ] `npm run package` → `dist/custom-color-palette-<version>.zip`.
- [ ] Confirm the zip has `manifest.json` at its root and does NOT contain
      `dev-reload.js` or `__tests__` (the package script prints its contents).

## 6. Permissions sanity

- [ ] Permissions still minimal: `storage`, `alarms`, and the three
      `docs.google.com` editor host surfaces only. Any addition is documented in
      `docs/PRIVACY.md` + `CHANGELOG.md`.
- [ ] If shipping with a config server: `CONFIG_BASE` set in
      `config/endpoints.js` and its origin added to
      `host_permissions`.

## 7. Submit

- [ ] Upload the zip in the Chrome Web Store Developer Dashboard.
- [ ] Paste the listing + privacy disclosure; answer the data-usage form per
      `STORE_LISTING.md`.
- [ ] (Org rollout) configure the `ExtensionInstallForcelist` / Workspace admin
      policy instead of / in addition to public listing.

## 8. Commit + push

- [ ] Commit the version bump + changelog; push.

## 9. Public mirror (after the store accepts the version)

The public repo, `jimbottle/workspace-custom-palette-public`, is the
production snapshot: it moves only on a release, one squashed commit per
version (owner decision 2026-11-05, bd `workspace-custom-palette-0mg`).

- [ ] The tag is the one `scripts/release.sh <version>` made on the release
      commit, which also dated the headings. The publish script refuses a tag
      whose notes still say Unreleased (`v0.2.2` was tagged before its roll
      and fails that check).
- [ ] `bash dev/publish-public.sh` builds the snapshot from the tag and runs
      the scrub denylist (kept outside the repo at
      `~/.config/raylytics/wcp-public-scrub.txt`), the local-data check and
      gitleaks, and leaves out `.github/` and the agent workflow files. It commits locally and stops.
- [ ] With the owner's go-ahead, `bash dev/publish-public.sh --push`. Never
      push private history or a non-release commit to the public repo.

## If something goes wrong

- "Version code already used" → bump `version` again; burned numbers can't be
  reused, gaps are fine.
- "Remotely hosted code" rejection → point the reviewer at the
  config-is-data-not-code note in `STORE_LISTING.md` / `docs/DEPLOY.md`.
